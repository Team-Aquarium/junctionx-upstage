## 1. 문제 정의

### 1.0 챌린지 요구사항과의 연결

트랙 챌린지는 이렇게 요구한다:

> *"Spot one repetitive task, recurring mistake, or everyday hassle caused by documents around you,
> and build a Document Agent service that goes beyond 'understanding' documents to actually
> **'getting the work done**.' Problems students genuinely relate to are especially encouraged."*

챌린지 Background가 예시로 든 문서(장학금 신청서, 계약서, 영수증) 중에서도
**공고문은 학생이 가장 자주, 반복적으로 마주치는 문서**다. 모아보라는 이 문서가 만드는
반복 작업 — "요강을 정독하고 내 조건과 대조하는 일" — 을 에이전트가 대신 끝내준다.

### 1.1 대학생의 공고 탐색은 비효율적이다

대학생이 접하는 기회(공모전·해커톤·장학금·대외활동·채용)는 대부분 **비정형 문서**로 유통된다.

| 문제 | 현실 |
| --- | --- |
| **포맷 파편화** | PDF 요강, HWP 첨부파일, 포스터 이미지(JPG), 게시판 HTML — 기계가 읽기 힘든 형태로 흩어져 있음 |
| **자격 요건이 본문에 묻힘** | "만 29세 이하 / 4학년 재학생 제외 / IT 관련 전공" 같은 핵심 조건이 수 페이지 요강 중간에 산재 |
| **판단 비용이 사용자에게 전가** | 공고 하나마다 요강을 정독하고 내 학년·전공·나이와 대조해야 함. 수십 건이면 수 시간 소요 |
| **놓치는 기회** | 채널이 분산되어(교내 공지, 위비티, 콘테스트코리아 등) 마감을 놓치거나 존재 자체를 모름 |

### 1.2 기존 서비스의 한계

- 위비티·콘테스트코리아 등 공고 **모음** 사이트는 존재하지만, 원문(첨부 HWP/PDF/포스터)을 **읽어주지는 않는다**.
- "지원 가능 여부"는 여전히 사용자가 직접 요강을 열어 판단해야 한다.
- 개인화 추천도 카테고리 필터 수준 — 프로필(전공·학년·기술 스택)과 대조하는 서비스는 없다.

### 1.3 핵심 인사이트

이 문제의 본질은 **비정형 문서 이해(Document AI)** 다.
공고 탐색의 병목은 "목록이 없어서"가 아니라 "문서를 읽고 나와 대조하는 비용" 때문이고,
이는 정확히 Upstage의 Document Parse → Information Extraction → Solar 추론 스택이 풀 수 있는 문제다.

## 2. 솔루션: 모아보라

**공고문을 던지면, 에이전트가 읽고, 내 프로필과 대조해 "지원 가능"까지 답해주는 서비스.**

챌린지가 요구하는 "이해(understanding)를 넘어 일을 끝내는(getting the work done)" 구조:

| 단계 | 기존 서비스가 멈추는 지점 | 모아보라가 끝내주는 일 |
| --- | --- | --- |
| 문서 이해 | 목록·원문 링크 제공까지 | HWP/PDF/포스터를 파싱해 구조화된 카드로 변환 |
| **판단** | 사용자가 요강을 읽고 스스로 판단 | 프로필 대조 → **지원 가능/미달/확인 필요 판정 + 사유** |
| **행동** | — | 제출 **체크리스트 생성**, 적합도 점수·이유로 **우선순위 결정**, 접수처 바로가기 |

```
비정형 공고문 (PDF·HWP·포스터·HTML)
        │
        ▼
[Upstage Studio 공고 에이전트]  Parse → Classify → Extract → Instruct
        │
        ▼
구조화된 공고 카드  (요약·자격 규칙·체크리스트·마감일)
        │
        ├──▶ 자격 판정 엔진 × 내 프로필  →  지원 가능 / 자격 미달 / 확인 필요
        │
        └──▶ Solar Pro 4 적합도 평가  →  0~100점 + 추천 사유 한 문장
```

### 2.1 사용자 여정

1. **프로필 만들기 (1분)** — GitHub/블로그 링크를 넣거나 재학증명서를 올리면 AI가 전공·학년·기술·관심사를 추출
2. **공고 모으기** — 파일 업로드, URL 붙여넣기, 또는 버튼 한 번으로 위비티·콘테스트코리아 자동 수집
3. **피드에서 확인** — 카드마다 지원 가능 여부 뱃지 + 적합도 점수 + 추천 사유가 붙어서 도착
4. **상세에서 행동** — 판정 사유(어떤 조건을 충족/미달했는지), 제출 체크리스트, 원문·접수처 바로가기

### 2.2 차별점

| 기존 공고 사이트 | 모아보라 |
| --- | --- |
| 목록 나열 | 문서를 **읽고 구조화** |
| 첨부파일은 직접 열어야 함 | HWP/PDF/포스터까지 에이전트가 파싱 |
| 자격 판단은 사용자 몫 | 규칙 기반 **자동 판정 + 사유 설명** |
| 카테고리 필터 | 프로필 대조 **Solar 적합도 점수 + 이유** |
| 결과만 표시 | **AI 실행 과정 전체를 실시간 공개** (신뢰성) |

## 3. Upstage 기술 활용 (트랙 요구사항 충족)

> 트랙 요구사항: *"Combine Studio agents — Parse · Classify · Extract · Instruct — and integrate
> with any service via REST APIs & webhooks. **Upstage Studio must power the core
> document-processing stages.**"*

### 3.1 Studio Agents가 핵심 처리를 담당

공고 인제스트의 모든 경로(업로드/링크/크롤링)는 **Studio 공고 에이전트**(`agt_Wq276WB3gsZygK6WnenGoa`)를 통과한다.
챌린지가 명시한 4개 노드를 전부 하나의 에이전트로 조합했다.

| 노드 | 역할 |
| --- | --- |
| 1. Parse | PDF·HWP·포스터 이미지 → 마크다운 (OCR 포함) |
| 2. Classify | 공모전/해커톤 · 대회 · 장학금 · 대외활동/서포터즈 · 채용/인턴 · 기타 6종 분류 |
| 3. Extract | 제목·주최·분야·자격 문구·접수 기간·발표일·혜택·문의·접수 URL 10필드 |
| 4. Instruct | 요약 불릿 + 자격 규칙 JSON(학년·학적·나이·전공·지역·팀 구성) + 제출 체크리스트 생성 |

### 3.2 REST API 통합 (외부 연동)

- **Studio Agents API** — `POST /v2/files` 업로드 → `POST /v2/responses` 실행 → Job 폴링으로 서비스에 통합
- **외부 소스 연동** — 위비티·콘테스트코리아 크롤러가 수집한 문서를 에이전트 파이프라인에 자동 투입
- **Document Parse / Information Extraction / Solar Chat** — 각각 REST API 직접 호출 (문서 챗 툴, 프로필 추출, 추천)

### 3.3 제품군 전체 사용

| Upstage 제품 | 사용처 |
| --- | --- |
| **Studio Agents** | 공고 처리 파이프라인 전체 (핵심) |
| **Document Parse** | 문서 챗의 `parse_document` 툴, 에이전트 1단계 |
| **Universal Information Extraction** | 재학증명서 → 프로필 추출, 문서 챗의 `extract_information` 툴 |
| **Solar Pro 4** | 적합도 평가(점수+사유), 링크 → 프로필 추출, 문서 챗 툴 오케스트레이션, reasoning 스트리밍 |

### 3.4 기술적 완성도 포인트

- **에이전트 출력 견고성** — Instruct의 이중 인코딩 JSON, 인용 마커(【†1】) 오염을 전처리로 해결
- **폴링 스냅샷 누적** — Studio Job 응답이 스냅샷마다 다른 노드를 담는 문제를 누적 맵으로 보존해 전 노드 중간 출력 시각화
- **투명한 AI** — 모든 AI 라우트가 NDJSON 스트림으로 단계·중간 산출물·Solar 추론을 실시간 공개
- **워크플로우 세션** — 새로고침해도 진행 중 작업에 재접속(이어보기), 중복 실행·중복 과금 방지
- **비용 최적화** — 파싱 sha256 캐시, 추천 결과 해시 캐시(프로필·공고 불변 시 재호출 없음)

## 5. 범위 정의 (3일 제약 내 우선순위)

### 5.1 해커톤 범위 (구현 완료)

3일 안에 "문서 이해 → 판단 → 행동"의 엔드투엔드 데모가 반드시 돌아가는 것을 최우선으로 잡고,
멀티 유저·알림처럼 데모 가치가 낮은 기능은 의도적으로 잘라냈다.

- 공고 인제스트 3경로 (파일/링크/크롤링 2사이트 5소스)
- Studio 에이전트 4단계 파이프라인 + 출력 견고성 처리
- 프로필 2경로 (링크 Solar 추출 / 서류 Information Extraction) + 병합
- 규칙 기반 자격 판정 (6종 규칙, 사유 설명)
- Solar 적합도 평가 + 캐시
- 실시간 워크플로우 스트리밍 + 세션 이어보기
- 문서 챗 (3툴 오케스트레이션 + reasoning)
- Supabase 클라우드 저장소, Docker 배포

### 5.2 의도적으로 제외 (데모 스코프)

- 다중 사용자 인증 (단일 사용자 프로필 가정)
- 알림 (마감 임박 푸시/이메일)
- 크롤링 스케줄러 (수동 트리거만)

### 5.3 확장 로드맵

| 단계 | 내용 |
| --- | --- |
| 1 | 멀티 유저 (Supabase Auth + RLS 정책 — 스키마가 이미 RLS 전제) |
| 2 | 마감 D-3 알림, 신규 적합 공고 알림 |
| 3 | 크롤링 소스 확장 (링커리어, 교내 공지 등) + 주기 수집 |
| 4 | 지원서 초안 생성 (프로필 × 공고 요강 → Solar 작성 보조) |
| 5 | 팀 빌딩 매칭 (같은 공고에 관심 있는 사용자 연결) |

## 6. 공식 평가 기준 대응

트랙 평가 기준(배점)에 맞춰 정리한다.

### Upstage Technology Implementation (30점)

> *에이전트 구성, 외부 통합, 구현의 난이도와 정확도*

- **에이전트 구성**: Parse → Classify(6종) → Extract(10필드) → Instruct(JSON 생성) 4노드 커스텀 에이전트. 모든 공고가 이 파이프라인을 통과하며 우회 경로 없음
- **외부 통합**: Studio Agents REST API(v2 files/responses/폴링) + 위비티·콘테스트코리아 크롤러 → 에이전트 자동 투입 + Supabase 저장소
- **난이도·정확도**: 이중 인코딩 JSON·인용 마커 정규화, 폴링 스냅샷 누적으로 전 노드 출력 보존, HWP·포스터 OCR, 첨부/본문 다중 문서 투입으로 추출 누락 방지
- 4개 제품군(Studio Agents · Document Parse · Information Extraction · Solar Pro 4) 전부 실사용

### Service Completeness (20점)

> *데모가 엔드투엔드로 안정적으로 도는가, 실서비스 수준의 화면·플로우·UX인가*

- 랜딩 → 프로필 → 등록/수집 → 피드 → 상세 → 문서 챗 전 플로우 동작, 실데이터(크롤링 공고)로 데모
- 워크플로우 세션으로 새로고침에도 진행 중 작업 이어보기 — 데모 중 사고 방지
- Upstage 브랜드 기반 미니멀 디자인 시스템, 다크 모드, 반응형 (별도 디자인 문서 참고)

### Idea Creativity (25점)

> *문제 발견이 신선한가, 기존 서비스와 구별되는가*

- 공고 "모음"이 아니라 공고 "판정" — 기존 위비티·콘테스트코리아가 멈추는 지점(원문 링크)에서 시작해 지원 가능 여부까지 답함
- 첨부 HWP·포스터 이미지까지 읽는 공고 서비스는 부재 — Document AI라서 가능한 차별점
- AI의 판정 사유·추론 과정을 전부 공개하는 투명한 UX

### Product Planning (25점)

> *구체적 타깃·문제 정의, 3일 제약 내 우선순위, 실서비스가 될 수 있는 화면·데이터 흐름 설계*

- 타깃·문제: §1, §4 — 학생이 실제로 겪는 반복 작업(요강 정독·자격 대조)을 구체적으로 정의
- 우선순위: §5 — 엔드투엔드 데모 최우선, 멀티 유저·알림은 의도적 제외 + 확장 로드맵 제시
- 설계: 화면·데이터 흐름은 `docs/기능명세서.md`(페이지·API·데이터 모델), `docs/디자인.md`(디자인 시스템)로 문서화 — 스키마가 RLS 전제라 멀티 유저 확장이 바로 가능

## 7. 데모 시나리오 (발표용)

1. **랜딩** — 서비스 콘셉트와 4단계 파이프라인 소개 (30초)
2. **프로필 등록** — 재학증명서 업로드 → Information Extraction 실시간 로그 → 프로필 완성 (1분)
