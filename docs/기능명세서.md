# 모아보라 — 기능 명세서

> JunctionX Korea 2026 · Upstage 트랙 — Team Aquarium
>
> 공고문(PDF·HWP·포스터)을 Upstage Studio 에이전트가 읽어 구조화된 공고 카드로 만들고,
> 개인 링크·서류로 만든 프로필과 대조해 **지원 가능 여부 판정**과 **맞춤 추천**까지 제공하는
> 공고 에이전트 서비스.

---

## 1. 서비스 개요

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 모아보라 |
| 핵심 가치 | 공고문을 읽지 않아도 "내가 지원할 수 있는가"를 즉시 판정 |

| 저장소 | Supabase 클라우드 (PostgreSQL + Storage) |
| 배포 | Docker (standalone 빌드) |

## 2. 페이지 기능

### 2.1 랜딩 `/`

| 기능 | 설명 |

| 히어로 | 서비스 소개 + 실제 `AnnouncementCard` 컴포넌트로 만든 분석 카드 예시 (데스크톱 2컬럼) |

| 통계 바 | 전체 / 지원 가능 / 마감 임박(D-7) / 맞춤 추천 건수 |

### 2.5 공고 상세 `/notice/[id]`

| 기능 | 설명 |
| --- | --- |
| 헤더 | 카테고리·자격 판정·D-day 뱃지 + 제목 + 주최 |
| Solar 적합도 카드 | 추천 결과가 있을 때만 점수 + 사유 표시 (fallback 없음) |
| 에이전트 요약 | Instruct 노드가 생성한 핵심 요약 불릿 |
| 자격 판정 사유 | 학년·학적·나이·전공·지역 등 규칙별 충족/미달/확인 필요 사유 목록 |
| 확인 필요 체크리스트 | verdict=`check`일 때 `reviewItems`를 확인 항목으로 표시, 클릭 체크 |
| 문서 챗 이어가기 | Review 항목을 질문으로 채워 `/chat?q=&notice=`로 이동 (원문 자동 첨부) |
| 제출 체크리스트 | 에이전트가 생성한 준비물 목록, 클릭 체크 가능 |
| 상세 요강 | 접수 기간(전체 폭) · 결과 발표 · 시상 및 혜택 · 문의 |
| 우측 고정 카드 | 접수 마감 D-day, **문서 챗으로 가져가기**, 공식 접수처/공고 페이지, 원문 파일 열기 |

### 2.6 문서 챗 `/chat`

| 기능 | 설명 |
| --- | --- |
| 문서 첨부 대화 | PDF·이미지·DOCX·PPTX·XLSX·HWP·HTML 최대 5개, 개당 50MB |
| 툴콜링 | Solar Pro 4가 3종 도구를 자율 호출 (최대 8스텝) |
| ├ parse_document | Document Parse — 문서를 마크다운으로 구조화 |
| ├ extract_information | Universal Information Extraction — 동적 스키마로 필드 추출 |
| └ run_studio_agent | Studio Agents — 공고 에이전트 파이프라인 실행 |
| 추론 표시 | 추론 수준 선택(끄기/낮음/보통/높음), 추론 과정 실시간 스트리밍 + 접기 |
| 공고에서 가져오기 | `/chat?notice={id}&q=` — `GET /api/files/[id]`로 원문을 받아 입력창에 자동 첨부, `q`는 질문 프리필 |
| ├ 상세 우측 버튼 | 분석용 기본 질문 + 원문 첨부 |
| └ Review 이어가기 | 확인 항목을 질문으로 채운 뒤 같은 원문 첨부 |
| 예시 프롬프트 | 자격·마감 요약 / JSON 추출 / 체크리스트 생성 (첨부 파일과 함께 전송됨) |
| 메시지 액션 | 응답 복사, 재생성, 대화 마크다운 내보내기, 새 대화 |
| 파싱 캐시 | 같은 파일 재파싱 방지 (sha256 메모리 캐시), 재과금 방지 |

## 3. AI 파이프라인

### 3.1 Studio 공고 에이전트 (`agt_Wq276WB3gsZygK6WnenGoa`)

```
[1] Document Parse   문서 → 마크다운 (OCR 포함)
[2] Classify         6종 분류: 공모전/해커톤·대회/장학금·대외활동·서포터즈/채용·인턴/others
[3] Extract          10필드: title, organizer, field, eligibility_text, apply_start,
                     apply_end, result_date, benefits, contact, apply_url
[4] Instruct         순수 JSON 출력: summary[], rules{}, todo_checklist[]
                     rules는 고정 6필드 + courses[] / preferred[] / review_items[] / etc
```

- Instruct 출력은 JSON 문자열로 이중 인코딩되어 오며, 인용 마커(【†1】)가 섞일 수 있음
  → `parseAgentJson`이 마커 제거 후 파싱 (파서 우회 금지)
- Job 폴링 스냅샷마다 담기는 노드 출력이 달라 `runStudioAgentDetailed`가 누적 맵으로 보존

### 3.2 자격 판정 엔진 (`lib/matching.ts`)

| 규칙 | 판정 로직 |
| --- | --- |
| 학년 (grades) | 프로필 학년 미포함 → 미달, 정보 없음 → 확인 필요 |
| 학적 (status) | 재학/휴학/졸업 한·영 표기 정규화 후 불일치 → 미달 |
| 나이 (min/max_age) | 출생연도 기준 초과/미달 → 미달 |
| 전공 (majors) | 토큰 분해 부분 일치 (예: "컴퓨터공학 관련" ↔ "컴퓨터공학과"), 불일치 → 확인 필요 |
| 지역 (region) | "전국·제한 없음·무관" 외에는 확인 필요 |
| 이수 과목 (courses) | 프로필로 검증 불가 → 확인 필요 (항목별 reviewItem) |
| 우대 (preferred) | 미충족이어도 탈락 아님 → 확인 필요 |
| 확인 조항 (review_items) | Instruct가 뽑은 애매 조항을 그대로 Review |
| 기타 (etc) | 평점·이수·수상·우대·제외 등 애매 키워드 → 확인 필요, 그 외 참고 |

- 최종 verdict: `eligible`(지원 가능) / `ineligible`(자격 미달) / `check`(확인 필요)
- `reasons`는 전체 판정 설명, `reviewItems`는 Review일 때 사용자가 확인할 항목만
- 판정 문구는 요청 locale(EN 기본 / KO)로 생성

### 3.3 Solar 맞춤 추천

- 프로필(학과·학년·관심사·기술·활동) × 공고 목록을 Solar Pro 4에 전달
- 공고별 score(0~100) + 60자 이내 추천 사유 한 문장 반환
- 프로필과 접점이 없으면 40점 미만 + 솔직한 사유
- **캐시**: 프로필 + 공고 id 집합의 sha256 해시가 같으면 재호출 없이 캐시 사용
- 추론 과정은 스트리밍으로 워크플로우 로그에 표시

### 3.4 웹 크롤러 (`lib/crawler.ts`)

| 항목 | 내용 |
| --- | --- |
| 지원 사이트 | 콘테스트코리아, 위비티 (둘 다 robots.txt Allow 확인) |
| 문서 우선순위 | 첨부 HWP/PDF > 본문 HTML > 포스터 이미지 |
| 콘테스트코리아 첨부 | `file_dn.php` 핸들러 감지, 앵커 텍스트에서 확장자 추출, "요강" > "신청서" 우선순위 |
| 보조 문서 | 첨부가 신청서라 정보가 부족한 경우 본문 HTML을 함께 에이전트에 투입 |
| 예의 | 요청 간 딜레이(politeDelay), 회당 최대 10건 |
| 링크 등록 라우팅 | URL 도메인·Content-Type 판별 → 전용 수집기 / PDF·이미지 직접 / 일반 HTML 본문 |

## 4. 실시간 워크플로우 시스템

| 기능 | 설명 |
| --- | --- |
| NDJSON 스트리밍 | AI 개입 라우트(ingest/crawl/link/profile/recommendations)는 모두 `application/x-ndjson`으로 단계·중간 산출물·Solar 추론을 실시간 전송 |
| 서버 세션 | `lib/workflow-session.ts` — globalThis 메모리에 세션 유지, 요청이 끊겨도 runner는 끝까지 실행 |
| 재접속(이어보기) | 같은 키로 재요청 시 버퍼된 이벤트 재생 + 라이브 이어보기 (새로고침 대응, 중복 실행 방지) |
| 세션 키 | `recommendations` / `crawl` / `link:{url}` / `profile-file` / `profile-link` / `profile-note` / `ingest:{id}` |
| 발견 API | `GET /api/workflows` (진행 중 세션 목록), `GET /api/workflows/attach?key=...` (재접속) |
| UI | `useWorkflowStream` 훅 + `WorkflowLog` — Solar 추론은 Reasoning 패널, 나머지는 Tool 패널로 렌더 (접기, 최대 높이, 최신 내용 자동 스크롤) |

## 5. API 명세

| 메서드 · 경로 | 응답 | 설명 |
| --- | --- | --- |
| `GET /api/announcements` | JSON | 공고 전체 + 프로필 매칭 verdict/score/reasons/reviewItems |
| `POST /api/ingest` | NDJSON | 파일 업로드 → 에이전트 실행 → 저장 → 판정 |
| `POST /api/ingest/link` | NDJSON | URL → 문서 수집 → 에이전트 실행 (중복 URL 거부) |
| `POST /api/crawl` | NDJSON | `{source, limit}` → 목록 크롤링 → 건별 인제스트 |
| `GET /api/recommendations` | NDJSON | Solar 적합도 평가 (해시 캐시) |
| `GET /api/profile` | JSON | 프로필 조회 |
| `POST /api/profile` | NDJSON | 서류 → Information Extraction → 병합 저장 |
| `PUT /api/profile` | JSON | 핵심 필드 직접 저장 (source=`manual`) |
| `DELETE /api/profile` | JSON | 프로필 초기화 |
| `POST /api/profile/link` | NDJSON | 링크 → Solar 추출 → 병합 저장 |
| `POST /api/profile/note` | NDJSON | 소개 글 → Solar 추출 → 병합 저장 |
| `GET /api/files/[id]` | binary | 공고 원본 파일 서빙 (상세 원문 열기 + 문서 챗 자동 첨부) |
| `POST /api/chat` | SSE | 툴콜링 챗 스트림 (reasoning 포함) |
| `GET /api/workflows` | JSON | 진행 중 워크플로우 세션 키 목록 |
| `GET /api/workflows/attach` | NDJSON | 기존 세션 재접속 |

> 주의: NDJSON 라우트는 Content-Type이 `application/x-ndjson`이므로 클라이언트에서
> `includes("json")`으로 일반 JSON과 구분하면 안 됨 (`application/json` 정확 매칭 필요).

## 6. 데이터 모델 (Supabase)

### 6.1 `announcements`

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| id | text PK | 8자리 랜덤 id (원본 파일명과 동일) |
| category | text | 6종 분류 |
| title / organizer / field | text | 제목 / 주최 / 분야 |
| apply_start / apply_end / result_date | text | 접수 시작·마감 / 발표일 |
| benefits / contact / apply_url | text | 혜택 / 문의 / 접수처 |
| summary | jsonb | 요약 불릿 배열 |
| rules | jsonb | 자격 규칙 (grades, status, min/max_age, majors, team_size, region, etc, courses, preferred, review_items) |
| todo_checklist | jsonb | 제출 체크리스트 배열 |
| source_file | jsonb | `{name, mediaType}` |
| source_url | text | 크롤링·링크 등록 시 원문 URL (부분 인덱스로 중복 방지) |
| created_at | timestamptz | 등록 시각 |

### 6.2 `profile` (단일 사용자, id=1 한 행)

jsonb 통짜 저장: name, university, department, grade, enrollment_status,
birth_year, interests[], skills[], activities[],
sources[] (`file` / `link` / `manual` / `note`)

### 6.3 `recommendation_cache` (id=1 한 행)

hash(프로필+공고 집합 sha256) · items[] · created_at

### 6.4 Storage `uploads` 버킷

원본 파일(PDF/HWP/이미지), 파일명 = 공고 id, 비공개(서버 service_role로만 접근)

### 6.5 보안

- RLS 전 테이블 활성화 + 정책 없음 → anon 키로 접근 불가
- 서버 전용 클라이언트(`lib/supabase.ts`)만 service_role 키 사용, 클라이언트 번들 import 금지
